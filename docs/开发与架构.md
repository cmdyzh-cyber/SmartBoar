# 聪明的野猪 / SmartBoar

让老打印机在 Apple Silicon Mac 上继续打印。一个原生 macOS 应用和 PKG 安装器，自动识别 USB 打印机，按完整型号匹配经过验证的驱动与修复方案。

**0.2.0 是可安装的试用原型，尚未完成新版安装包的真实安装、出纸和干净系统验证。** 它已通过原生编译、隔离队列配置/回滚测试、安装包内容检查和界面检查。它不是通用驱动大全，也不会为未知设备自动生成驱动。

## 使用

1. 接上 USB 打印机并打开电源。
2. 打开 PKG，由 macOS 安装程序申请管理员授权。
3. 从“应用程序”打开“聪明的野猪”。只有一台已适配设备且没有旧任务时，安装阶段自动设置；否则在应用中选择设备并点击“自动设置”。
4. 放好一张 A4 纸，点击“打印一页测试”，确认完整出纸且没有重复。

用户无需安装 Homebrew、Python 或 Xcode，也无需执行终端命令。应用每 10 秒只读重新检测设备；接入设备不会在后台自动打印。

## 当前覆盖

| 状态 | 机型 |
|---|---|
| 驱动与设备修复方案已实测，可自动设置 | HP Laser 108a，USB 03F0:E82A，完整 USB 产品名 HP Laser 108a |
| 已有识别条目，Mac 方案待验证，不开放安装 | Samsung ML-1510、ML-1610、ML-1660、ML-2010、SCX-4200、SCX-4300；Xerox Phaser 3117、3160；Dell 1100、1110 |
| 未知设备 | 显示可读取的设备型号和支持状态，可保存诊断，不修改打印机 |

108a 的驱动和 USB 修复方案已在 M3 MacBook Air / macOS 14.6 实际打印一页，并验证重新插拔 USB 后完整出纸、没有重复；这项证据来自此前的设备修复，不能等同于本安装包已经完成实际安装验证。

10 个候选机型的上游来源是 [SpliX 官方列表](https://openprinting.github.io/splix/)。上游报告可用不代表本项目已完成 macOS 实测。只纳入识别记录，不随意套用 108a 驱动。USB 使用厂商自定义接口、没有标准打印机类接口的某些设备可能尚不能识别。

## 0.2 的自动适配框架

- `src/usb.c` 只读扫描标准 USB 打印机类设备，并输出厂商、产品、VID/PID、序列号和连接位置。读扫描不打开设备接口。独立接口切换仍只允许精确匹配的 HP 108a。
- `resources/catalog.json` 描述机型匹配、支持状态、模块、连接方案和验证记录。产品名精确规范化匹配；同一 USB ID 下名称不同的设备不自动安装。名称对应多个规则时拒绝猜测。
- 原生配置管理器加载适配库。驱动文件独立放在模块目录，并在构建后记录 SHA-256；管理员配置前检查模块哈希及安装目录所有权/写权限。现阶段模块引擎为 CUPS raster，USB 动作仅 `none` 与限定的 `hp108a-classic`。
- 模块和机型描述可以扩展；集成测试已验证添加第二个测试机型规则后，管理器无需改代码即可完成配置和恢复。测试机型不会进入安装包。
- 所有生产路径在编译时固定。测试工具的模拟路径和权限替代只存在于测试编译，不能通过生产程序的环境变量启用。

当前适配库内置，随安装包更新。**没有在线驱动下载服务、远程适配库更新、网络打印机自动设置、Windows 或 Intel Mac 支持。** 后续在线模块需要可信签名、固定来源、版本和系统兼容校验；不能把网络上的任意 PPD/驱动交给管理员直接执行。

## 设备设置与恢复

只设置所选设备按厂家/型号 URI 和序列号精确对应的 USB 队列。检测到多个对应队列、重复设备标识、不安全/缺失序列号或未完成任务时停止。默认打印机不变。

对 108a 保留已修复的 SpliX 方案和原生 macOS USB backend。只调整该设备的 IPP-over-USB 桥接状态与接口，不禁用全局 USB/IPP 服务，不关闭 SIP。原有兼容 SpliX PPD 的选项保留，只更新过滤器路径。

原队列 PPD、URI、启用/暂停状态及设备桥接状态在修改前备份到 `/Library/Printers/LegacyPrint/StateV2/<设备哈希>/snapshot.json`，目录 0700，文件 0600。重复设置保留首次备份，安装失败尝试恢复本次操作前状态。应用的“恢复原设置”恢复首次备份。没有旧队列时恢复会删除本软件新建的队列。恢复前检查旧任务和 URI；连接被独立修改时停止，以免影响另一设备。

“清除旧任务”由用户单独确认，只暂停和取消选中队列。安装程序不会取消旧任务，也不会发送测试页。测试按钮每次只提交一份 A4 单面文档。内部缓存已接收的任务可能需要打印机关机再开机。

软件新建的打印队列显示 `聪明的野猪 · <实际机型>`，已有队列的显示名称保留。应用恢复配置后，应用和未使用驱动文件仍留在系统中；恢复不是卸载。

## 诊断信息

“保存诊断信息”由用户选择保存位置，文件包含系统版本、设备 USB 厂商/产品标识、产品名和匹配状态。不包含序列号、设备哈希、队列 URI、用户名或本地路径，不自动上传。

## 开发与构建

在 Apple Silicon Mac 安装 Xcode Command Line Tools，并为开发脚本准备 Python 3：

```sh
bash build.sh
python3 tests/integration_checks.py
pkgutil --expand-full release/SmartBoar-0.2.0-arm64-unsigned.pkg build/release-expanded
python3 tests/package_checks.py
```

Python 仅用于构建、测试，不随软件安装。应用、USB 工具和管理器都是原生 ARM64 程序。构建中的模块哈希在代码签名之后计算。安装包使用 root:wheel 所有权，安装脚本仅包含 `postinstall`。

驱动对应源码在 `vendor/SpliX-fixed-source.tar.gz`，随安装包一起提供。在开发环境解压后，进入 `splix-build` 运行 `make DISABLE_JBIG=1` 可重建；原上游 Makefile 的开发库搜索路径可能需要按环境调整。最终运行无需这些开发工具。详见 `THIRD_PARTY.txt`。

新增机型流程见 [docs/增加机型.md](增加机型.md)。验证详情见 [docs/验证与发布.md](验证与发布.md)。

## 发布状态与许可

当前 PKG 未使用 Developer ID 签名，也未公证；内部程序仅有本地临时签名。下载后可能被系统阻止。对外发布之前需完成开发者签名、公证与实际安装测试。

原生应用、管理器与 USB 工具原创部分为 MIT；SpliX、PPD 和第三方补丁保留上游 GPL 许可与声明。对应源码随安装包和项目提供。没有打包专有 HP 驱动，不隶属于 HP、Apple 或任何打印机厂商。
