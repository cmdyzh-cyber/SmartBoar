# 增加机型

识别与安装支持是两件事。先建立识别记录，完成 Mac 原生驱动、通信和实际打印验证后，才将该机型从 `catalog-only` 改为 `verified`。

## 识别记录

在 `resources/catalog.json` 的 `profiles` 增加唯一 `id`、`model`、`family`、`support`、`match`、`notes`、`verification`、`sources`。

`match.products` 是完整 USB 产品名称的明确别名，比较时仅忽略大小写、空格和标点。不做包含或近似型号匹配。`vendorIds` 是数字 VID；`usbIds` 是有证据的 VID/PID 对。需要型号与厂商同时符合；`requireUsbId: true` 还要求 VID/PID 同时符合。不能凭猜测填入 PID，不使用宽泛的系列名来开放安装。

候选记录示例：

```json
{
  "id": "vendor-example-100",
  "model": "Vendor Example 100",
  "family": "Candidate driver family",
  "support": "catalog-only",
  "match": {
    "vendorIds": [4660],
    "usbIds": [],
    "products": ["Vendor Example 100"],
    "requireUsbId": false
  },
  "notes": "仅识别，尚未完成 Mac 实测。",
  "verification": [],
  "sources": []
}
```

上面的标识为示例，不能直接作为真实设备记录。

## 驱动模块

模块声明 `engine: cups-raster`、相对 `filter` 路径、许可证、对应源码归档。机型声明 `module`、相对 `ppd` 路径、固定 USB `uriTemplate`（唯一占位符 `{serial}`）、`queueSlug`、`architectures`、`minimumMacOS`、`usbAction` 和可选的 `preservePPDMarkers`。

构建脚本放入模块文件并签名，`scripts/build_catalog.py` 为过滤器和该模块所有 PPD 计算哈希，生成安装目录的适配库。开发用源适配库允许 `assets` 为空，最终安装包必须有实际哈希。增加第二模块时同步修改构建脚本，复制其驱动、PPD、许可证与对应源码。它不需要另写一个队列管理器。

`usbAction: none` 不调整桥接和接口。`hp108a-classic` 只能用于该精确机型；不能将其复制到其他 HP 或其他厂商设备。新的通信修复动作必须在原生代码实现，并有明确目标范围和失败恢复测试。适配库不支持任意 shell 命令、外部安装脚本或运行时环境变量覆盖。

## 开放安装所需证据

1. USB 型号和 VID/PID 有真实检测记录；共享 USB ID 下其他型号不会误匹配。
2. 驱动是可运行的 ARM64 Mac 程序，许可证允许分发，必要时随包提供完整对应源码。
3. PPD 和文档转换通过；A4 等支持纸张尺寸正确。
4. 安装包在目标 macOS 安装，实际完整出纸，不重复；重新插拔 USB 后复测。对彩色、双面等功能分别声明实测范围。
5. 备份、重复安装、旧任务拦截、失败恢复和手动恢复通过；同机其他打印机配置不变。

`verification` 写明系统、芯片、测试项目和证据范围。不写用户序列号、用户名或个人文件路径。只有上游列表支持、模拟测试通过或 CUPS 显示任务完成，都不构成真实出纸证据。

未完成验证时保持 `catalog-only`。没有驱动或无法识别时，保留诊断出口，不尝试安装名字相近的驱动。
